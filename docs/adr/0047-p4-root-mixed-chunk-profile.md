# ADR-0047: Closed optional Root9 API chunk profile

Status: proposed; design direction accepted, implementation and qualification pending.

Date: 2026-11-17
Decision: [Delegated Lead direction](https://github.com/Tanveerahamed-Dev/baby-thanos/issues/7#issuecomment-6931265377).

The genuine v1 nine-case API payload exceeded Linux's owned-call runtime window.
Windows refused in the same first-batch interval; its native reason is unrendered.
Neither v1 run emitted a final receipt or uploaded evidence. Compiler acceleration,
a precise expensive inner case and 420-second v2 feasibility are not established.

Keep `root9-v1` as the constructor default. It retains two API processes,
383 inventory entries, 384 retained files and hosted receipt schema /1.
The newly defined v2 markers are refused under v1; valid v1 bytes remain unchanged.
No captured file, payload count, unknown schema or failed run selects a profile.

The trusted opt-in `root9-three-case-v2` fixes three ordered three-case chunks
per seed. For each seed, API chunks 0/1/2 precede the original nine full CLIs.
Each existing case occurs exactly once per seed; all 18 API analyses and 18 CLIs,
seeds 1/83, workers 1/4, input orders and independent oracle bytes remain required.
Six exact labels are `api0-0` through `api0-2` and `api1-0` through `api1-2`.
Profile selection precedes root creation and is bound to root ownership identity.
An observed change cannot be restored into a healthy capture owner.

API chunk schema is `atlas-brain.p4-root-mixed-api-chunk/2`, with prefix
`P4_ROOT_MIXED_API_CHUNK `. Its exact record binds profile, context, batch,
chunk, seed, three fixed cases, api_runs=3 and denial counts 4/0.
The finalizer independently requires all six ordered records, rejecting mixed,
missing, duplicate, reordered, grafted, extra or mistyped records.
Hosted schema /2 adds `execution_profile`; CLI and business report schemas stay /1.
V2 has 24 analysis/CLI children plus separate before/after Git context checks,
52 parent stages, 343 original input, oracle and report files plus 48 stdio files: 391 inventory entries,
then DIGESTS.json gives 392 retained files. Six API probes total 24 denials;
each of 18 full CLIs retains its separate forty-denial witness.

Keep 90-second owned calls, all native cleanup reserves, the single shared
420-second parent deadline and 600-second job limit. Keep 4 MiB file/frame and
16 MiB tree limits, input checks after every child, actual Git bracketing,
typed oracle/witness checks, publication failures and success-AND-true upload.
No retries, fallback, adaptive chunks, cache or removed compiler phase.

This prerequisite adds owner-profile support only. It activates no workflow,
changes no analyzer, and proves no process origin, performance or demo success.
Later consumer work must preserve legacy defaults, retain sequential same-process
cross-case semantic coverage and establish genuine Linux AND Windows completion,
all hosted gates, independent review, named Lead merge and fresh native proof.
P4 acceptance and M1/field/platform/release qualification are not established.
Historical EI provenance remains UNVERIFIED. P5/release work remains excluded.
