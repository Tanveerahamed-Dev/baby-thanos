# ADR-0029: Conditional reported EtherChannel protocol discrepancies

Status: proposed.

The public evaluate_protocol_comparisons(root, budgets, policies) API invokes the
accepted source-bound preparation once afresh. It admits no supplied Store, plan,
execution or prepared carrier. Original source/whole-profile proof closure precedes checks.

EC owns a separate check Step reading ONLY reported_protocol. It reads and validates
ALL original EC subjects before any finding, even empty policies or unselected groups.
The lower evaluator trusts application-closed facts/population/intent; it is no origin seal.

Under explicit DECLARED same_reported_protocol intent, identified LACP/PAgP
disagreement yields a conditional supplied-report discrepancy. Genuine Unknown
reason/detail/needs propagate exactly, including None detail and empty needs. When both
participants are Unknown, the first canonical participant supplies the primary reason;
both original FactRefs remain available through the source.
Observed '-' stays Known none_reported in source; its check is NOT_OBSERVABLE,
requesting an unprintable explicit negotiation operand. Equal untimed reports are
AS_OF_MISSING, never healthy. Time/policy requests do not promise health or mode proof.

Policy RegistryRefs and original FactRefs remain inspectable through the original
preparation. Coverage stays open. No parser/Writer replay, peer/mode/static/member/
min-links inference, default profile/report/CLI change, R-ID/P4/EX-02/M1/field or P5 claim.
