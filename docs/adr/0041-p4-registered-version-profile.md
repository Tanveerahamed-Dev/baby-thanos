# ADR-0041: Closed local reported protocol-version ownership

Status: proposed; design acceptance does not qualify runtime implementation.

The FHRP profile owns l3.fhrp.reported_protocol_version and the fixed parse_hsrp_all_version step and show standby all operation.
compile_version_profile verifies the literal contract and matches actual canonical catalogue/registration bytes and digest to a separately compiled literal declaration; callers cannot provide a profile.
The planned producer consumes that factory before one cache-owned parser batch and again afterward, including empty input.
Every actual receipt must correspond to the first compiled registration, original request/capture, operation, owner and context.
Original input and target/node pointers and detached values remain in custody throughout that invocation.
The owning raw-claim verifier closes the current parser graph before each parser-value snapshot traversal and before any Writer.
All declared subjects, raw columns, block ownership, caches, canonical values and proof spans close before VERSION-only Store writes.
Reported literal 1/2 requires an explicit header token and authenticated IPv4 witness in the same complete block.
Missing captures, subjects, version or address-family evidence remain Unknown with their original reasons and evidence needs.
Version remains an operand; existing local subjects and declared logical keys do not change.
Compiled catalogues and returned results are inspectable metadata, never source admission or value seals.
The profile unit is limited to registration; actual custody/production requires its own implementation, tests and exact-head review.
GLOBAL composition, whole-source/proof/Reader closure and fresh conditional logical comparison remain required.
Legacy STATE/VIP/default profiles and report bytes stay fixed; no field, full P4/M1/P5 or numbered correlation acceptance is added.
